# 工数見積りルール

開発工数を 1〜5 段階で見積もる。
正確な見積りではなく、意思決定の材料として使う概算値。

## 工数レベル定義

| Level | 目安期間 | 条件 |
|-------|---------|------|
| 1 | 半日〜1日 | 既存ツールの設定変更、単一スクリプト。技術的な不確実性がほぼない |
| 2 | 2〜3日 | 複数スクリプトの組み合わせ、API 連携 1 つ、簡易的な UI |
| 3 | 1〜2週間 | 簡易 Web ツール、外部 API 連携 2 つ以上、データ変換ロジックあり |
| 4 | 2〜4週間 | Web システム（認証・DB 付き）、複数画面、テスト・デプロイ環境の構築が必要 |
| 5 | 1ヶ月以上 | 複数部門が使うシステム、複雑な権限管理、既存システムとの連携が必要 |

## 評価軸

工数レベルは以下の 4 軸で総合判断する。

| 評価軸 | 観点 |
|--------|------|
| 機能の技術的難易度 | 定型的な CRUD か、複雑なロジックが必要か。外部 API 連携の数と複雑さ |
| 利用ツールの難易度 | 使い慣れた技術で実現できるか。新しいツールの学習コストがあるか |
| 要件定義の難易度 | 利用者の人数。1人なら明確、複数部門なら調整コストが発生する |
| 運用・インフラの複雑さ | 環境構築、監視、バックアップ、継続的なメンテナンスの有無 |

## カスタマイズ例

- チームのスキルに合わせて目安期間を調整する
- 社内の承認フローが重い場合、Level 3 以上に調整日数を加味する
