# 実装規模の最小化ルール

実装手段の優先順位。上位の手段で解決できるなら、下位の手段を選ばない。
組織の技術スタックや方針に合わせて編集できます。

## 優先順位

| 優先度 | 手段 | 適用条件 |
|--------|------|---------|
| 1 | 既存ツールの設定変更 | 設定だけで解決する場合 |
| 2 | スクリプト / CLI ツール | エンジニアが使う定型作業、バッチ処理 |
| 3 | 既存ツールの組み合わせ | 複数ツールの連携で解決する場合 |
| 4 | 簡易 Web ツール（認証なし） | 少人数（2〜5人）が使う簡単な画面 |
| 5 | Web システム（認証・DB 付き） | 6人以上、複数部門、データ永続化が必要 |

## 判断の原則

- システム開発以外の選択肢を必ず検討する
- Q3（影響人数）と Q6（最小構成）の回答をもとに判断する
- 検討結果はブリーフの `solution_scale` に反映する

## カスタマイズ例

- ローコードツール（Retool 等）がある場合、優先度 4 の前に挿入する
- セキュリティポリシーで認証必須の場合、優先度 4 を削除する
